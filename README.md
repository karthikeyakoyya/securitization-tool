# Securitization Document Intelligence & Cash Flow Toolkit

Built against the Deloitte Analyst, Secured Transactions and Support JD
(Securitization / Audit & Assurance). Two modules:

- **Module A — Document Abstraction:** extracts structured fields (tranche
  terms, payment dates, servicer/trustee, covenants) from a real SEC-filed
  ABS offering document, flags low-confidence extractions for human review,
  and scores accuracy against manually-verified ground truth.
- **Module B — Cash Flow / Investor Analytics Engine:** a simplified
  sequential-pay waterfall that computes declining balance schedules,
  weighted average life (WAL), and approximate pre-tax yield per tranche,
  with a stratification table and a formatted Excel export.

## AUP-style procedures & results work paper

`backend/app/aup_workpaper.py` assembles a "Procedures & Results" work
paper — the document tier below a signed Agreed-Upon Procedures (AUP)
report (see the JD line "assist with Agreed Upon Procedures Report
issuance"). It is explicitly **not** a signed AUP report: a real one is
issued by an accounting firm to specified parties under engagement
authority this project doesn't have, and the output says so on its first
page rather than implying otherwise.

Every procedure and result in it is generated by re-running this
project's own extraction, scoring, and cash flow code against the two
real filings — nothing is hand-written prose describing fictional
findings. Run `python3 -m app.aup_workpaper` from `backend/` to print the
underlying JSON, or open `backend/workpapers/AUP_Procedures_and_Results_Workpaper.docx`
for the rendered version. Two honesty notes baked into the output itself:
the cash-flow scenario assumptions (CPR/default/WAC) are labeled as
illustrative, not stated in the offering documents; and the CMBS
pool-concentration procedure runs against a synthetic property-type mix
(the real loan-level collateral tape isn't in the prospectus summary and
wasn't separately sourced), with that caveat printed directly above the
result so it can't be mistaken for a real finding about that deal.

## Real data, stated plainly

Two sample documents, both manually-trimmed excerpts of real, public SEC
EDGAR filings, saved for offline development/testing of the extraction
pipeline:

1. `backend/sample_data/raw/vw_alt_2025b_424b5_excerpt.txt` —
   Volkswagen Auto Lease Trust 2025-B, Form 424B5, filed 2025-09-11.
   https://www.sec.gov/Archives/edgar/data/1182534/000141057825002125/tm2524548d14_424b5.htm
2. `backend/sample_data/raw/benchmark_2024_v7_424b2_excerpt.txt` —
   Benchmark 2024-V7 Mortgage Trust (CMBS conduit deal), Form 424B2, filed
   2024-05-24. https://www.sec.gov/Archives/edgar/data/1258361/000153949724001104/n4255_x13-424b2.htm
   Servicer/trustee names cross-checked against the deal's Pooling and
   Servicing Agreement (Exhibit 4.1 to Form 8-K/A, filed 2024-05-30).

Each has a hand-verified ground truth file in `backend/sample_data/ground_truth/`,
scored by `score_field_level_accuracy()`:

| Document | Field-level accuracy |
|---|---|
| VW Auto Lease Trust 2025-B (ABS) | **90.3% (28/31 fields)** |
| Benchmark 2024-V7 (CMBS) | **71.0% (22/31 fields)** |

Real, visible failure cases on both documents (a deal nickname the
summary-of-terms table doesn't state, an exact trustee-role phrasing, a
slightly different collateral-type description; on the CMBS document, the
WAC-linked classes' coupon type and rate — see "Extending to a second
asset class" below). This is intentional: a defensible accuracy number
with honest misses is worth more in an interview than a claimed 100%.

**Scoring bug fixed while adding the second document.** The original
scorer counted two fields that were both correctly left blank (extractor
`None`, ground truth `None`) as a *mismatch*, and compared numeric fields
(e.g. `212600000.0` vs `212600000`) as raw strings, so a numerically
correct extraction with a different float/int representation also
scored as wrong. Both bugs affected every document scored, not just the
new one — fixing them moved the original ABS document's number from
67.7% to 90.3%. Worth naming plainly in an interview: the first number
was real but the scorer undercounted it.

**Scope boundary, stated up front:** this project only sources publicly
filed ABS/RMBS/CMBS documents (Form 424B5, 424B2, 8-K exhibits, ABS-EE)
from SEC EDGAR. CLO private-placement offering circulars (Rule 144A) are
not public and are explicitly out of scope — don't claim otherwise in an
interview.

## Extending to a second asset class

Adding the CMBS document surfaced real, structural gaps in code that was
originally built against one auto-ABS filing's exact layout — this
section is the honest account of what generalized cleanly and what
didn't:

- **Class-naming regex.** The original tranche-row pattern only matched
  `Class A-<digit>` (e.g. `Class A-2-A`). CMBS conduit deals use
  letter-suffixed classes (`Class A-S`) and single-letter subordinate
  classes (`Class B`, `Class C`, ...) that don't carry a numeric rank in
  the label. Generalized the regex to match both, and made seniority
  fall back to document order when no digit is present — which is only
  correct because this document happens to list classes in seniority
  order, not because the extractor understands CMBS subordination
  structure. Stated as a real limitation, not fixed further.
- **Field labels differ by asset class.** Auto-ABS uses "Servicer/
  Sponsor:" and "Indenture Trustee:"; this CMBS deal uses "Master
  Servicer:" and "Trustee:" (with Certificate Administrator as a
  separate, same-entity role). `_FIELD_PATTERNS` now tries a list of
  label variants per field instead of one hardcoded label.
  `deal_name_series` still isn't extracted for either document — no
  regex was added for it, since neither excerpt states the deal's short
  ticker name in a consistently labeled spot.
  Also generalized the ground-truth filename lookup in
  `routers/documents.py`, which previously hardcoded the `_424b5_excerpt`
  suffix and would not have resolved a `_424b2_excerpt` filename.
- **No shared date column.** The ABS table's 4th column is always a
  per-tranche final payment date; the CMBS Certificate Summary table's
  4th column is a rate-type label (Fixed / WAC / WAC Cap) instead —
  CMBS classes here share one deal-wide "Rated Final Distribution Date"
  (May 2056) rather than per-class dates. The row regex now captures a
  generic 4th column and only parses it as a date when it looks like
  one; the ground truth records the per-tranche date as unstated
  (`null`) for the CMBS deal, which is a genuine structural difference,
  not a missing value.
- **WAC-linked rates don't fit the binary coupon-type schema.** Three of
  the five CMBS classes pay a rate capped at the pool's weighted average
  coupon (WAC/WAC Cap) — not a fixed contractual rate, and not indexed
  to a market rate like SOFR either. The schema's `CouponType` enum is
  Fixed/Floating only. Rather than force a label, the extractor flags
  these with an explicit reason and defaults to Fixed (the code's
  pre-existing behavior for anything it can't parse); ground truth
  records them as `floating` (closer, since the rate varies with the
  pool) — a deliberate, documented mismatch rather than a bug to chase.
  A real fix would add a third `CouponType` value; noted as a next step,
  not done here.

## Module B on a second, differently-shaped deal

Ran the cash flow engine unmodified against the CMBS deal's five real
tranches (illustrative assumptions: 8% CPR, 1% annual default, 6.2%
collateral WAC, 60-month term — not the actual deal's own model). It
produced a sane WAL ladder by seniority (Class A-1 ≈ 0.08y up to Class B
≈ 4.0y) with no code changes, confirming the sequential-pay engine isn't
tied to the ABS deal's specific tranche count or naming. One honest
observation from the run: Class B's approximate pre-tax YTM came out
negative, because at this deal's steep subordination and a 60-month
term, the most junior class receives interest but very little principal
within the window — an artifact of the model's stated scope ("no real
collateral performance simulation"), not a computation bug, and worth
naming as such if asked.

## VBA macro: pool-concentration QA

`backend/vba/StratificationQA.bas` is a standalone VBA module (openpyxl
can't write macros into the `.xlsx` files it generates, so this is
imported separately, not emitted by Python) that automates a real
due-diligence check on the Stratification tab from `excel_export.py`:
color-flags any pool bucket (property type, state, FICO band, etc.) at
or above a concentration threshold (default 20% red, 10-20% amber), and
writes a one-line summary of how many buckets were flagged and their
combined pool share. Import via Excel &gt; Alt+F11 &gt; File &gt; Import
File..., run `FlagConcentrationRisk` from Alt+F8, save as `.xlsm` to
keep it attached. See the header comment in the file for the exact
column layout it expects.

## What Module B does and does NOT do

**Does:** simplified sequential-pay principal allocation (senior class
retires first; classes sharing a seniority rank, like Class A-2-A/A-2-B,
split pro rata), collateral amortization under a constant-CPR prepayment
assumption plus a flat annual default rate, WAL, an IRR-based approximate
pre-tax yield, a pool stratification table, and a formatted Excel export.

**Does NOT do:** pro-rata/turbo structures, interest-shortfall
carryforward, trigger-driven priority-of-payments switches, or any real
collateral performance simulation (defaults/prepayments are single flat
assumptions, not curves). It does not simulate future SOFR paths for the
floating-rate tranche — you supply an assumed all-in rate for the run. This
is a demonstration of the underlying mechanics for a portfolio project, not
a substitute for Intex/Bloomberg. Say this plainly if asked.

## Running it

### Backend

```bash
cd backend
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

Verified working end-to-end in development (extraction, accuracy scoring,
waterfall run, and Excel export all tested via FastAPI's TestClient before
packaging). Try it directly:

```bash
# List bundled sample documents
curl http://localhost:8000/api/documents/sample-files

# Run Module A extraction + accuracy scoring on the real sample filing
curl -X POST http://localhost:8000/api/documents/extract-sample/vw_alt_2025b_424b5_excerpt.txt

# Get a ready-made Module B request built from the same deal's real tranche terms
curl http://localhost:8000/api/cashflow/sample-request

# Run the waterfall
curl -X POST http://localhost:8000/api/cashflow/run \
  -H "Content-Type: application/json" \
  -d @<(curl -s http://localhost:8000/api/cashflow/sample-request)

# Download the Excel workbook
curl -X POST http://localhost:8000/api/cashflow/export-excel \
  -H "Content-Type: application/json" \
  -d @<(curl -s http://localhost:8000/api/cashflow/sample-request) \
  -o cashflow_export.xlsx
```

Interactive API docs at `http://localhost:8000/docs` once the server is running.

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Opens at `http://localhost:5173`, proxying `/api` to the backend on `:8000`.
Two tabs: **Document Review** (Module A — run extraction on the sample
filing, see flagged fields and accuracy vs. ground truth) and **Cash Flow**
(Module B — run the waterfall, see WAL/YTM per tranche, a declining-balance
chart, and a Download Excel button).

## Extending with the LLM extraction layer

`backend/app/extraction.py` includes an `LLMExtractor` stub for
OpenAI-backed structured-output extraction (useful for covenant language
that doesn't fit the regex layer's table-row pattern, or for scaling past
this one document's exact format). It's inactive without an
`OPENAI_API_KEY` — implement `_call_openai()` to wire it up. The heuristic
extractor is what the bundled demo and accuracy number use, since it needs
no external API key to run.

## Adding more real documents

1. Search SEC EDGAR full-text search (https://www.sec.gov/edgar/search/)
   for Form 424B5 / 424B2 / 8-K exhibits filtered to ABS/RMBS/CMBS issuers.
2. Save the relevant excerpt (Summary of Terms + Priority of Payments
   sections work well) to `backend/sample_data/raw/`.
3. Manually fill in a matching ground-truth JSON in
   `backend/sample_data/ground_truth/`, following the schema in
   `vw_alt_2025b_ground_truth.json`.
4. `HeuristicExtractor` is pattern-matched to this filing's specific table
   format — a materially different layout (e.g. an RMBS shelf deal, or a
   PDF instead of HTML) will need either regex adjustments or the
   LLM-extraction path.
